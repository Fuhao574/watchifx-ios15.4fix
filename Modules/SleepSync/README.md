# 手动睡眠配置同步（开发中）

现有模块入口：WatchFix首页 → 功能 → 睡眠配置同步 → 设置。
不新增App，不增加首页独立功能入口；内部模块标识沿用 FocusConfigCompatibility。
不是常驻开关，不随打开页面/刷新自动同步；正常功能与一次单独的用户确认绑定。

**设备端运行不依赖 OpenSSH。** 开始、状态读取、取消和恢复均走 App 内桥接与本机
persona／launchd；不连接 SSH、不需要密码、网络端口或开发电脑在线。
卸载 OpenSSH 不应改变该执行链路；目前为源码契约检查通过，尚未完成无 OpenSSH 真机验收。

首版只提供手机上手动同步一次 Sleep：打开模块、确认开始、按提示正常保存一次睡眠设置、
查看协议结果并结束恢复。不做持续自动同步、其他 Focus 模式或通话转发修复。
默认运行清单 `enabledForDevice=false`；品牌绑定测试版已在本轮手机完成单次同步与撤回，
用户报告功能测试通过。这不等于其他设备或持续同步已验证；不要手改清单绕过构建限制。

## 代码

- `ModuleSession.h`：daemon启动捕获一个会话，目录/权限/时钟/取消检查与身份一次收据。
- `Runtime/Focus`：从成功的once3独立派生，nested内容3、额外最多一次Sleep，无控制升级。
- `Runtime/Identity`：从identitywireless派生，身份受本会话专用marker控制，不用全局shadow偏好。
- `RootLauncher.sh`：固定start/recover及UUID，不接受任意程序/路径/服务参数。
- `SleepSyncCoordinator.sh`：阶段记录、四文件备份/校验、有限身份/Focus重启、撤销恢复。
- `stage_runtime.py`：只把组件放进App私有资源；默认禁用，可显式生成品牌绑定的设备测试候选。

不要直接在主机或设备执行两个shell脚本。离线测试只对固定路径翻译后的fixture使用完整mock。

## 构建

在项目根目录使用 `make package` 的**本机打包目标**，默认包含模块；
不要使用 `make do` / install。完整日志和限制在工作区 reports 中。
正常AppsSupport/Messages/Pairing源不改。沿用FocusConfigCompatibility卡片，改为无常驻安装内容的
手动操作模块；不安装旧实验 dylib，也不参加“全部安装／删除”。
功能卡片提供“设置／删除”：删除前必须无活动会话、恢复已验证、四个实验注入路径不存在。
删除仅注销模块并禁止新同步，进入未安装列表；重新安装只恢复注册，不安装旧常驻库。
历史会话、备份和消耗凭据保留，不能因删除／重装重置上一轮发送权限。

只有维护者准备明确的本机测试包时，才同时指定 `WATCHFIX_SLEEP_SYNC_BRAND`（显式十六进制）
和 `WATCHFIX_SLEEP_SYNC_TEST_CANDIDATE=1`。App会核对本机jbrand与构建绑定一致；不匹配拒绝开始。
这些构建选项不是对真实设备操作的授权，也不代表已经通过设备验收。

### 构建来源更正

随后核验发现该轮App携带的是旧组件目录产物：递归Theos实际更新了顶层obj，staging却取
组件目录旧obj。因此该轮不能当作新日志权限实现的设备验收，尽管旧产物确实产生了本轮日志。
两处递归构建已显式绑定各自object目录，staging新增源码mtime新于二进制则拒绝打包的检查。
两个组件重编译后hash均变化，与App内字节一致；正确新产物已替换到手机并核验，没有新建
第二轮会话。失败分类提示已随此App部署；历史会话不改写为新结果，不伪造诊断或ACK。

### once3迁移核对

converter、返回观察器、identity clone/native契约与once3基准一致；发送/ACK wrappers仅日志标签变化。
新增固定hash回归防止将协议核心改动误当封装修正。实际模块wrappers套用原离线29场景全部通过
（原生派发/权限为host mock）；实际Session+TrialPermit头文件合并测试11场景通过，权限/取消/
过期/替换/消费凭据不依赖coordinator mock。新worker必须先从当前Focus PID的私有日志确认
startup lease claimed=YES及hooks enabled=YES才显示等待保存；单有PID不算就绪，原期限不续期。
以上是迁移一致性与主机证据，不将上轮无出站记录推断为协议失败或用户漏保存。
